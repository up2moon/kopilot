# 프론트엔드 에이전트 가이드

## 우선 참고 순서
프론트엔드 화면이나 사용자 흐름을 수정할 때는 아래 순서로 문서를 확인합니다.

1. 루트 `AGENTS.md`
2. `frontend/FRONT.md`
3. `kopilot-design/DESIGN.md`
4. `kopilot-design/PRD.md`
5. 작업 대상 화면과 관련된 `kopilot-design/docs/features/*.md`

## 와이어프레임 활용 규칙
`kopilot-design/DESIGN.md`와 `kopilot-design/PRD.md`에는 Figma 와이어프레임 링크와 화면별 요구사항이 정리되어 있습니다. 로그인, 회원가입, 첫 로그인 초기 설정, 대시보드, 소비 상세, AI 챗봇, 랭킹, 챌린지, 투자효과, 마이 화면을 구현하거나 수정할 때는 해당 Figma 링크와 기능 문서를 먼저 확인하세요.

화면 구조, 주요 문구, CTA, 하단 탭, 플로팅 챗봇 버튼, 모바일 기준 너비(`390px`)는 와이어프레임을 우선합니다. 구현 중 디자인 문서와 기존 코드가 충돌하면 사용자에게 확인하거나, 변경 이유를 작업 결과에 명시하세요.

## 페이지 경로 관리
새 프론트엔드 페이지나 화면 전환 경로를 만들면 이 문서에 경로와 화면 목적을 기록하고, 이후 관련 작업 전 반드시 참고합니다. 경로는 PRD의 권장 라우팅과 맞추는 것을 우선하며, 임시 경로를 만들면 임시임을 명시하세요.

현재 페이지 경로:

- `/login`: 로그인 화면. 대시보드와 동일한 Kospay 로고와 `소비 분석 → 절약 코칭 → 자산 시뮬레이션` 가치 흐름을 보여줍니다. `POST /api/auth/login`과 연동하며 성공 시 토큰을 저장하고 마이데이터 연동 상태에 따라 `/dashboard` 또는 `/first-login/mydata-connect`로 이동합니다. `테스트 계정으로 시작`은 랜덤 이름·이메일·비밀번호로 `POST /api/auth/signup`을 호출하고 반환된 인증 정보로 즉시 최초 온보딩에 진입합니다.
- `/signup`: 회원가입 화면. 비밀번호 확인 일치 여부를 검증한 뒤 `POST /api/auth/signup`과 연동하며 성공 시 `/login`으로 이동합니다.
- `/first-login`: 첫 로그인 초기 설정 화면. 환영, 마이데이터 안내, 소비 카테고리 선택, 카테고리별 월 예산 목표 설정, 임시 완료 화면을 제공합니다.
- `/first-login/mydata-connect`: Figma `268:36`에 대응하는 마이데이터 연동 완료 화면. `마이데이터 연동하기` 이후 처리 중 로딩 상태와 연동 완료 상태를 보여주고 소비 카테고리 선택으로 이어집니다. `나중에 하기`를 누르면 소비 목표 설정 없이 온보딩을 완료합니다.
- `/dashboard`: 홈 대시보드 화면. 마이데이터 소비 요약 카드, AI 절약 코치 추천 카드, 일자별 소비 추이 차트, 카테고리별 지출 현황, 소비 인사이트, 최근 5건 결제 내역, 자주 이용한 가맹점 목록을 제공합니다.
- `/spending`: 내 소비 상세 서브페이지 (대시보드 소비 상세 보기).
- `/coach`: AI 절약 챗봇 서브페이지 (플로팅 챗봇 버튼 클릭 시 이동).
- `/ranking`: 익명 랭킹 서브페이지 (하단 탭 2번째).
- `/challenge`: AI 주간 챌린지 페이지 (하단 탭 3번째). `GET /api/users/me/challenges`로 이번 주 미션과 진행 상태를 조회한다. 기본 추천 미션 외에도 AI 채팅에서 미션을 계속 추가할 수 있어 총개수는 가변적이다. 프로토타입에서는 시간 제한 없이 `인증하기`를 활성화하고, `POST /api/users/me/challenges/verify`가 미인증 미션 중 최소 1개 이상을 서버에서 무작위 성공 처리한다. 인증 결과에는 성공 개수, 포인트, 예상 절약액을 표시하며 성공 미션이 있으면 컨페티와 `투자효과 보기` CTA를 제공한다. CTA는 `/investment-effect?category=savings&month=YYYY-MM`으로 이동한다.
- `/investment-effect`: 투자효과 시뮬레이션 서브페이지 (하단 탭 4번째). 기존 소비 카테고리 외에 `절약액`을 제공하며, 선택 월에 성공한 챌린지의 예상 절약액 합계를 투자 원금으로 계산한다.
- `/my`: 마이 페이지 (하단 탭 5번째).

마이데이터가 연동되어 있지 않은 사용자가 로그인하거나 `/dashboard` 등 앱 메인 화면에 진입하면 마이데이터 연동 화면(`/first-login/mydata-connect`)으로 라우팅됩니다. 마이데이터 연동 완료 후 `/dashboard`로 진입할 수 있습니다.

주요 앱 화면(`/dashboard`, `/ranking`, `/challenge`, `/investment-effect`, `/my`)에서는 하단 5개 탭 바(`BottomNav`)와 우측 하단 플로팅 챗봇 버튼(`FloatingChatbot`)을 공통 모듈로 노출합니다.

투자효과 화면은 주식·ETF 후보를 최대 20개 기본 목록으로 먼저 불러옵니다. 검색어 입력 시 전체 종목 마스터를 서버에서 검색해 최대 20개 결과를 표시하고, 입력을 지우면 캐시된 기본 목록으로 즉시 복귀합니다.
종목 선택 후 시뮬레이션을 다시 계산할 때는 기존 결과와 종목 목록을 유지해 스크롤 위치가 초기화되지 않도록 하며, 화면 상단에 작은 재계산 상태를 표시합니다.
투자효과의 조회 연월은 브라우저 지역 설정과 무관하게 `YYYY-MM` 형식으로 표시합니다. 표시 버튼을 누르면 연도를 이동하고 12개월 중 하나를 고르는 월 캘린더가 열리며, 월 선택 즉시 조회합니다.
`절약액` 카테고리는 선택 월에 `SUCCESS`로 완료된 챌린지의 `estimated_saving_amount`만 합산합니다. 합계가 없으면 시세 조회 대신 `NO_SAVINGS` 빈 상태와 `챌린지 보러 가기` CTA를 표시합니다.

랭킹 화면 상단은 `GET /api/users/me/consumption-dna`로 월간 소비 DNA 별명·요약·4개 성향 축을 표시하며, 전체 랭킹 각 사용자 행에는 저장된 해당 월 DNA 별명을 함께 표시합니다.

최초 마이데이터 연동과 마이페이지 재연동 중에는 카드·은행·간편결제 데이터가 KoPilot로 이동하는 공통 연결 애니메이션을 표시합니다. 마이페이지 재연동 중에는 중복 조작을 막는 모달형 진행 화면을 사용합니다.

투자효과 fallback이 실패하면 로컬 개발 모드에서 백엔드가 제공한 오류 코드, 메시지, 종목/거래일 메타를 접을 수 있는 `실패 상세` 영역에 표시합니다. 운영 빌드에서 이 영역이 필요하면 프론트엔드 빌드 시 `VITE_INVESTMENT_DEBUG_ERRORS=true`, 백엔드 런타임에 `INVESTMENT_DEBUG_ERRORS=true`를 함께 설정해야 합니다.

AI 절약 챗봇의 추천 질문은 입력창 위에서 접고 펼칠 수 있는 아코디언으로 표시합니다. 접은 상태에서도 `추천 질문 보기 (개수)` 바를 유지하며, 추천 질문을 선택하면 대화 영역 확보를 위해 자동으로 접습니다.
추천 질문 `이번 주 미션 만들기`는 `CREATE_WEEKLY_CHALLENGE` 액션으로 채팅 API에 전달합니다. 요청마다 이번 주 챌린지 1개를 추가하며, 완료 메시지와 `챌린지 보기` CTA를 표시한 뒤 채팅 화면에 머뭅니다. 사용자가 CTA를 눌렀을 때만 `/challenge`로 이동합니다. `clientAction.highlightChallengeId`는 이동 후 추가된 카드로 스크롤하고 `방금 추가됨` 강조 효과를 표시하는 데 사용합니다. 채팅 API가 반환한 `clientAction`은 허용된 내부 경로(`/challenge`)만 실행합니다.

## AI 챌린지 연동

- 페이지 컴포넌트: `src/pages/ChallengePage.jsx`
- API 클라이언트: `src/services/challenges.js`
- 기능 명세: `kopilot-design/docs/features/ai-challenge.md`
- 화면은 로딩, API 오류 재시도, 온보딩 필요, 이번 주 미션 미생성, 주간 미션 목록과 인증 가능 상태를 구분해 표시한다.
- 챌린지 생성은 백엔드에서만 수행한다. 프론트엔드는 임의로 미션을 만들거나 수정하지 않고 저장된 API 응답을 표시한다.
- 프로토타입 주간 인증은 요일과 시각 제한 없이 실행한다. 서버가 미인증 미션의 결과를 한 번만 무작위 확정하며, 새로고침이나 재인증으로 결과를 다시 뽑지 않는다.
- 인증 결과에 성공 미션이 하나 이상 있으면 접근성을 해치지 않는 짧은 컨페티 효과를 한 번만 재생한다. `prefers-reduced-motion: reduce` 환경에서는 애니메이션을 생략하고 성공 메시지만 표시한다.
- 인증 결과에는 성공 개수와 포인트뿐 아니라 성공 미션의 예상 절약액 합계도 표시한다.
- 미션 카드는 유사한 제목과 설명을 나누지 않고 거래 근거와 목표를 합친 단일 문장으로 표시한다. 인증 전에는 `진행중` 배지를 숨기고 인증 결과가 확정된 뒤에만 `성공` 또는 `미완료`를 표시한다.
- 개발 환경의 `CHALLENGE_TEST_NOW`가 적용된 조회 응답(`clock.testMode=true`)에는 화면 상단에 `개발 테스트 시간 사용 중` 배너와 적용 시각을 표시한다.
- 각 미션에는 API의 `difficulty`와 `point`를 사용해 `쉬움 · 50P`, `보통 · 100P`, `어려움 · 150P`를 표시한다.


## 구현 기준
현재 프론트엔드는 React 19 + Vite 기반입니다. `frontend/src/` 안에서 컴포넌트와 스타일을 관리하고, 컴포넌트는 `PascalCase`, 훅과 헬퍼는 `camelCase`를 사용합니다. 화면 변경 후에는 `npm run lint`와 `npm run build`를 실행해 검증합니다.
