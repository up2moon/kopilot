# AI 채팅 기반 주간 절약 챌린지 추가

## 1. 목적과 범위

AI 절약 챗봇의 추천 질문 `이번 주 챌린지 만들기`를 단순 조언 응답이 아니라 실제 챌린지 추가로 연결한다.

사용자가 추천 질문을 누르거나 채팅으로 챌린지 생성을 명확히 요청하면 AI가 Kospay 내부 Function Tool을 호출한다. 서버는 로그인 사용자의 실제 거래내역을 기준으로 이번 주 챌린지 1개를 추가하고 채팅에 완료 메시지와 `챌린지 보기` 버튼을 표시한다. 사용자가 버튼을 눌렀을 때만 `/challenge` 화면으로 이동한다.

MVP 범위는 다음과 같다.

- 추천 질문 `이번 주 챌린지 만들기`에 생성 액션을 부여한다.
- 자유 입력의 명확한 생성 요청에서도 동일 Tool을 호출한다.
- 한 번의 Tool 호출마다 새로운 챌린지 1개를 추가한다.
- 한 주에 보유할 수 있는 챌린지 개수를 고정하거나 5개로 제한하지 않는다.
- 이동한 화면에서 새로 추가된 챌린지를 자동 스크롤과 강조 효과로 안내한다.
- 마이데이터 또는 거래내역이 부족하면 생성하지 않고 필요한 다음 행동을 안내한다.

다음 항목은 MVP에서 제외한다.

- 사용자가 목표 금액이나 보상 포인트를 직접 지정하는 기능
- 기존 챌린지를 삭제하거나 교체하는 기능
- AI가 서버 검증 없이 자유 형식 챌린지를 DB에 저장하는 기능
- 챌린지 수행 기간이 지난 뒤 이번 주 챌린지를 추가하는 기능
- 채팅의 자기 신고만으로 인증 결과나 포인트를 확정하는 기능

## 2. 핵심 원칙

### 2.1 AI와 서버의 책임 분리

AI는 사용자의 생성 의도를 파악하고 Function Tool을 호출한다. 실제 생성 가능 여부, 기준 거래내역, 목표값, 예상 절약액, 난이도, 포인트는 서버가 결정한다.

```text
사용자 요청
→ AI가 챌린지 생성 의도 판단
→ create_weekly_saving_challenge Tool 호출
→ 서버가 로그인 사용자와 현재 KST 주차 확인
→ 기존 챌린지 수 다음 sequence로 챌린지 1개 추가
→ Tool 결과를 AI에 반환
→ AI 완료 메시지와 챌린지 보기 버튼 표시
→ 사용자가 버튼 클릭
→ 프론트엔드가 /challenge로 이동
→ 추가된 카드로 스크롤하고 강조 효과 표시
```

AI가 Tool 인자로 `userId`, 포인트, 목표 금액, 챌린지 상태를 전달하거나 임의로 변경할 수 없게 한다. `userId`는 인증 미들웨어의 `req.user.id`만 사용한다.

### 2.2 가변 개수의 주간 챌린지

- 기본 주간 생성은 처음 진입한 사용자에게 추천 챌린지를 준비할 수 있다.
- 채팅 생성 요청은 기존 챌린지를 덮어쓰지 않고 항상 새로운 챌린지 1개를 추가한다.
- 기존 챌린지가 5개 이상이어도 추가할 수 있으며 별도 최대 개수는 두지 않는다.
- 각 챌린지는 `(user_id, week_start_date, sequence)` 유니크 제약으로 구분한다.
- 동시 요청은 사용자 행 잠금과 다음 sequence 계산으로 중복 저장을 방지한다.

### 2.3 생성과 인증의 분리

채팅 Tool은 챌린지 추가까지만 수행한다. 성공 여부 판정과 포인트 지급은 `POST /api/users/me/challenges/verify` 정책을 사용하며, 인증 시 이번 주에 존재하는 전체 챌린지를 일괄 판정한다.

## 3. 사용자 흐름

### 3.1 추천 질문에서 생성

1. 사용자가 AI 절약 챗봇에 진입한다.
2. 추천 질문에서 `이번 주 챌린지 만들기`를 누른다.
3. 사용자 메시지 버블에 같은 문구를 표시한다.
4. 입력창과 추천 질문을 비활성화하고 생성 중 상태를 표시한다.
5. 백엔드가 `create_weekly_saving_challenge` Tool을 한 번 실행한다.
6. AI 메시지 `새로운 절약 챌린지를 추가했어요.`를 표시한다.
7. 자동으로 이동하지 않고 채팅 화면에 머문다.
8. 사용자가 `챌린지 보기` 버튼을 누르면 `/challenge`로 이동한다.
9. 새 카드로 스크롤하고 `방금 추가됨` 배지와 강조 효과를 약 4초간 표시한다.

`prefers-reduced-motion: reduce` 환경에서는 카드 애니메이션을 최소화한다.

### 3.2 자유 입력에서 생성

다음처럼 생성 의도가 명확한 표현은 동일한 Tool 호출 대상으로 처리한다.

- `이번 주 챌린지 만들어줘`
- `내 소비로 절약 챌린지 하나 추가해줘`
- `지금 할 수 있는 챌린지 시작할래`

생성 방법이나 추천만 묻는 표현은 Tool을 실행하지 않고 상담 답변을 제공한다.

## 4. 추천 질문과 채팅 API 계약

추천 질문은 일반 질문과 생성 액션을 구분할 수 있도록 `action`을 포함한다.

```json
{
  "id": "create-weekly-challenge",
  "label": "이번 주 챌린지 만들기",
  "action": "CREATE_WEEKLY_CHALLENGE"
}
```

`POST /api/users/me/saving-bot/chat` 요청은 선택적인 `requestedAction`을 받는다.

```json
{
  "message": "이번 주 챌린지 만들기",
  "requestedAction": "CREATE_WEEKLY_CHALLENGE",
  "recentMessages": []
}
```

- 명시적 추천 질문 액션이면 `requestedAction`을 전송한다.
- 일반 텍스트 입력은 `requestedAction`을 보내지 않는다.
- 알 수 없는 액션 값은 `400`으로 거절한다.
- 명시적 액션 요청에서는 해당 Function Tool 호출을 강제한다.

## 5. OpenAI Function Tool

```json
{
  "type": "function",
  "name": "create_weekly_saving_challenge",
  "description": "로그인 사용자가 이번 주 절약 챌린지를 실제로 만들어 달라고 명확히 요청할 때 새로운 챌린지 1개를 추가한다.",
  "strict": true,
  "parameters": {
    "type": "object",
    "additionalProperties": false,
    "properties": {},
    "required": []
  }
}
```

Tool 실행기는 다음 규칙을 따른다.

- 허용 목록에 등록된 Tool만 실행한다.
- `req.user.id`를 서버 실행 컨텍스트로 사용한다.
- 한 요청에서 변경성 Function Tool은 최대 한 번 실행한다.
- `MAX_COUNT`, `MAX_SPEND`, `NO_SPEND` 유형과 난이도별 포인트 계산은 기존 챌린지 도메인 규칙을 재사용한다.
- 내부 SQL, 스택, 원본 거래 목록은 모델이나 클라이언트에 노출하지 않는다.

생성 성공 결과:

```json
{
  "status": "CREATED",
  "weekStartDate": "2026-07-27",
  "weekEndDate": "2026-07-31",
  "challengeId": 77,
  "challengeCount": 6,
  "estimatedSavingAmount": 9500,
  "challenge": {
    "id": 77,
    "content": "지난 주에는 카페·간식 결제를 3번 했네요. 이번 주에는 카페·간식 결제를 2번으로 줄여볼까요?",
    "type": "MAX_COUNT",
    "targetCount": 2,
    "targetAmount": null,
    "point": 50
  },
  "destination": "/challenge"
}
```

`challengeCount`는 추가 후 이번 주의 전체 개수이며 최대값이 아니다. `challengeId`는 이동 후 새 카드를 식별하는 용도로 사용한다. `challenge.content`는 DB에 저장되고 챌린지 화면에 표시되는 문구와 동일한 값이다.

거래내역 부족은 `ONBOARDING_REQUIRED`, 생성 기간 종료는 `CREATION_CLOSED`로 반환하고 `destination`은 `null`로 둔다.

## 6. 생성 가능 시간과 데이터 정책

- 새 챌린지는 월요일 `00:00:00` 이상 토요일 `00:00:00` 미만에만 추가한다.
- 모든 시간 계산은 `Asia/Seoul`을 기준으로 한다.
- 개발 환경의 `CHALLENGE_TEST_NOW`가 적용되면 기존 챌린지 API와 동일한 테스트 시간을 사용한다.
- 같은 주의 모든 챌린지는 월요일부터 금요일까지 함께 수행한다.
- `challenge_date`는 주 시작일을 기록하고 실제 순서는 `sequence`로 구분한다.
- 과거의 `(user_id, challenge_date)` 유니크 인덱스는 제거하고 `(user_id, week_start_date, sequence)` 유니크 인덱스를 사용한다.

## 7. 채팅 API 응답과 화면 전환

```json
{
  "answer": "새로운 절약 챌린지를 추가했어요!\n\n지난 주에는 카페·간식 결제를 3번 했네요. 이번 주에는 카페·간식 결제를 2번으로 줄여볼까요?\n\n챌린지 화면에서 바로 확인해보세요.",
  "inScope": true,
  "evidence": [],
  "suggestedQuestions": [],
  "toolResult": {
    "name": "create_weekly_saving_challenge",
    "status": "CREATED",
    "challengeId": 77,
    "challengeCount": 6,
    "challenge": {
      "id": 77,
      "content": "지난 주에는 카페·간식 결제를 3번 했네요. 이번 주에는 카페·간식 결제를 2번으로 줄여볼까요?"
    }
  },
  "clientAction": {
    "type": "NAVIGATE",
    "path": "/challenge",
    "highlightChallengeId": 77
  }
}
```

- 프론트엔드는 `NAVIGATE`와 `/challenge` 조합만 허용한다.
- 생성 성공 답변의 챌린지 문구는 모델이 새로 작성하거나 요약하지 않고 서버가 `challenge.content`로 확정한다.
- 챌린지 조회 API도 같은 저장 문구를 반환해 채팅과 카드의 내용을 일치시킨다.
- `highlightChallengeId`는 양의 정수만 허용한다.
- 이동 직전 강조 대상과 60초 만료 시각을 `sessionStorage`에 저장한다.
- 챌린지 조회 후 ID가 실제 응답에 있을 때만 강조한다.
- 저장값은 한 번 소비하여 새로고침 때 오래된 효과가 반복되지 않게 한다.
- 어떤 응답에서도 자동 이동하지 않는다.
- 생성 성공 응답에만 `챌린지 보기` 버튼을 표시한다.

## 8. 오류 및 안전

| 상황 | 동작 |
|---|---|
| 마이데이터 미연동 또는 거래내역 없음 | 필요한 소비 정보 안내 후 채팅 화면 유지 |
| 기존 챌린지가 여러 개 존재 | 기존 내용을 유지하고 다음 sequence로 1개 추가 |
| 토·일 생성 요청 | 다음 주 월요일부터 생성 가능하다고 안내 |
| 알 수 없는 Tool 요청 | 실행하지 않고 서버 오류 처리 |
| Tool 실행 후 최종 AI 문구 생성 실패 | 검증된 고정 완료 문구 반환 |
| 사용자가 이동 버튼을 누르지 않음 | 채팅 화면에 그대로 머물며 생성 결과 유지 |
| 사용자가 빠르게 여러 번 클릭 | 진행 중에는 추가 요청 차단 |

- 인증 사용자 외의 ID는 Tool에 전달하지 않는다.
- 포인트와 예상 절약액은 서버 계산값만 사용한다.
- 채팅 문장으로 챌린지를 성공 처리하거나 포인트를 지급하지 않는다.
- `clientAction.path`는 서버와 프론트엔드 양쪽에서 허용 목록으로 검증한다.

## 9. 검증 및 완료 조건

### 백엔드

- [ ] 명시적 액션 요청에서 Function Tool이 정확히 한 번 실행된다.
- [ ] 요청마다 기존 챌린지를 유지한 채 새로운 챌린지 1개가 추가된다.
- [ ] 기존 챌린지가 5개 이상이어도 추가할 수 있다.
- [ ] 동시 요청에도 sequence가 중복되지 않는다.
- [ ] 거래내역이 없으면 `ONBOARDING_REQUIRED`를 반환한다.
- [ ] 토·일에는 `CREATION_CLOSED`를 반환한다.
- [ ] Tool 실행만으로 포인트가 지급되거나 챌린지가 성공 처리되지 않는다.

### 프론트엔드

- [ ] 생성 완료 후 채팅 화면에 머물며 `챌린지 보기` 버튼을 표시한다.
- [ ] 사용자가 `챌린지 보기` 버튼을 눌렀을 때만 `/challenge`로 이동한다.
- [ ] 이동 후 추가된 카드가 화면 중앙에 오고 강조 효과가 표시된다.
- [ ] 카드에 `방금 추가됨` 배지가 표시된다.
- [ ] `챌린지 보기` CTA로 즉시 이동할 수 있다.
- [ ] 잘못된 경로나 ID는 실행하지 않는다.
- [ ] 모션 감소 설정에서 불필요한 애니메이션을 생략한다.
- [ ] 성공과 오류 상태 모두 자동으로 이동하지 않는다.

### 전체

- [ ] 한 주 챌린지 개수에 5개 제한이 없다.
- [ ] 인증 결과는 `성공 개수/전체 개수`로 표시된다.
- [ ] 기존 토요일 일괄 인증, 포인트 지급, 랭킹 정합성을 유지한다.
