# 프로토타입 챌린지 즉시 인증 및 절약액 투자효과

## 1. 문서 목적

현재 프로토타입에서는 주간 챌린지를 토요일까지 기다린 뒤 실제 거래내역으로 검증하는 흐름보다, 사용자가 즉시 성공 경험과 보상을 확인하는 흐름이 더 중요하다.

따라서 다음 두 기능을 하나의 경험으로 연결한다.

1. 시간 제한 없이 `인증하기`를 누르면 이번 주 챌린지 중 일부를 무작위로 성공 처리한다.
2. 폭죽을 터트리는 모션을 통해 성공 처리가 됐다는 것을 보여주고 `투자효과 보기` 버튼을 누르면 `투자효과` 페이지에서 절약액을 바탕으로 투자했을때 얼마인지 보여준다.
3. 성공한 챌린지의 예상 절약액을 월별로 합산해 투자효과 페이지의 `절약액` 카테고리에서 별도로 시뮬레이션한다.

핵심 사용자 경험은 다음과 같다.

```text
챌린지 수행
→ 즉시 인증
→ 일부 챌린지 성공 및 예상 절약액 획득
→ 투자효과의 '절약액' 카테고리
→ 절약한 돈의 미래 가치 확인
```

이 문서는 프로토타입 정책을 정의한다. 기존 `ai-challenge.md`, `ai-challenge-verification.md`의 토요일 인증 제한과 거래내역 기반 판정 규칙은 이 기능이 적용되는 동안 사용하지 않는다.

---

## 2. 해결하려는 문제

### 현재 문제

- 챌린지 인증이 특정 요일과 시각 이후에만 가능해 짧은 프로토타입 시연에서 성공 경험을 보여주기 어렵다.
- 성공 보상이 포인트와 순위 변화에 집중되어 절약의 실질적인 가치를 체감하기 어렵다.
- 투자효과 페이지가 소비한 돈의 기회비용만 보여주어 챌린지 성공과 직접 연결되지 않는다.

### 개선 목표

- 사용자가 언제든 `인증하기`를 눌러 즉시 결과를 확인한다.
- 프로토타입에서도 매번 최소 1개 이상의 성공 결과를 경험한다.
- 성공한 챌린지의 예상 절약액을 명확한 보상처럼 보여준다.
- 절약액이 투자효과의 원금으로 이어져 `절약 → 미래 자산 가치` 흐름을 완성한다.

---

## 3. 기능 범위

### 포함

- 챌린지 인증 시간 제한 제거
- 서버에서 미인증 챌린지의 성공 대상을 무작위 선정
- 성공 챌린지별 기존 포인트 지급
- 성공 챌린지의 예상 절약액 합산 및 인증 응답 제공
- 투자효과 카테고리에 `절약액` 추가
- 선택 월에 성공한 챌린지의 예상 절약액 합계를 투자 원금으로 사용
- 절약액이 없는 월의 빈 상태 제공
- 재인증 시 결과 및 보상이 중복되지 않는 멱등성 보장

### 제외

- 실제 증권 주문 또는 금융상품 가입
- 실제 계좌로 절약액 이체
- 종목 추천 또는 매수 유도
- 거래내역을 이용한 실제 챌린지 성공 여부 판정
- 사용자가 성공 결과를 직접 선택하거나 다시 뽑는 기능
- 성공 결과를 초기화하고 재추첨하는 기능

## 4. 챌린지 즉시 랜덤 인증

### 4.1 화면 정책

- 미인증 챌린지가 하나 이상 있으면 요일과 시각에 관계없이 `인증하기` 버튼을 활성화한다.
- 기존의 `토요일 00:00부터 인증할 수 있어요`, `오후 12시부터 인증할 수 있어요` 등 시간 제한 안내는 제거한다.
- 버튼 아래 보조 문구가 필요하면 `이번 주 챌린지 결과를 바로 확인해 보세요`를 사용한다.
- 인증 중에는 중복 클릭을 막고 기존 로딩 및 오버레이를 유지한다.
- 인증 완료 후 다음 정보를 표시한다.
  - 성공 개수/전체 개수
  - 획득 포인트
  - 이번 인증으로 얻은 예상 절약액
  - 각 챌린지의 `성공` 또는 `미완료` 상태
- 성공 챌린지가 하나 이상이면 기존 컨페티 효과를 한 번 재생한다.

결과 문구 예시:

```text
3/5 챌린지 성공!
300P와 예상 절약액 18,500원을 얻었어요.
```

`estimated_saving_amount`는 실제 계좌 잔액이 아니라 챌린지 목표를 달성했을 때 아낄 것으로 추정한 금액이므로 화면에서도 `예상 절약액`으로 표현한다.

### 4.2 랜덤 판정 규칙

판정은 프론트엔드가 아닌 백엔드에서 수행하고 DB에 저장한다.

1. 현재 사용자의 이번 주 챌린지를 조회한다.
2. `IN_PROGRESS` 상태인 챌린지만 랜덤 판정 대상으로 삼는다.
3. 대상이 `N`개라면 성공 개수를 `1`부터 `N` 사이에서 무작위로 정한다.
4. 대상 챌린지를 무작위로 섞고 앞에서 성공 개수만큼 `SUCCESS`, 나머지를 `FAIL`로 확정한다.
5. 성공 챌린지별 포인트를 기존 `point_ledger` 규칙으로 지급한다.
6. 성공 챌린지의 `estimated_saving_amount` 합계를 계산한다.
7. 상태 변경과 포인트 지급은 하나의 DB 트랜잭션으로 처리한다.

프로토타입의 보상 경험을 위해 챌린지가 하나 이상이면 최소 1개는 성공한다. 단, 챌린지가 없으면 기존과 같이 `CHALLENGE_NOT_FOUND` 오류를 반환한다.

### 4.3 재인증과 추가 챌린지

- 이미 `SUCCESS` 또는 `FAIL`로 확정된 챌린지는 다시 추첨하지 않는다.
- 동일한 챌린지에 포인트를 중복 지급하지 않는다.
- 모든 챌린지가 이미 확정된 상태에서 재요청하면 기존 결과를 그대로 반환하고 컨페티를 다시 재생하지 않는다.
- AI 채팅으로 같은 주에 새 `IN_PROGRESS` 챌린지가 추가되면 새 챌린지만 다음 인증의 랜덤 판정 대상이 된다.
- 새 챌린지 인증 결과에는 기존 성공 챌린지를 포함한 현재 주 전체 성공 개수와 누적 예상 절약액을 반환한다.

### 4.4 조회 응답 정책

`GET /api/users/me/challenges?week=YYYY-MM-DD`

- `canVerify`: 현재 주에 `IN_PROGRESS` 챌린지가 하나 이상이면 `true`
- `verificationOpensAt`, `verificationClosesAt`: 프로토타입 UI에서 사용하지 않는다.
- 하위 호환이 필요하면 기존 필드를 유지하되 인증 가능 여부 판정에 사용하지 않는다.
- 모든 챌린지가 확정되면 `canVerify=false`, `resolved=true`를 반환한다.

### 4.5 인증 API

`POST /api/users/me/challenges/verify`

요청 본문은 없으며 기존 인증 경로를 유지한다.

응답 예시:

```json
{
  "weekStartDate": "2026-07-27",
  "status": "VERIFIED",
  "successfulCount": 3,
  "totalCount": 5,
  "earnedPoints": 300,
  "successfulSavingAmount": 18500,
  "showCelebration": true,
  "message": "3/5 챌린지 성공! 300P와 예상 절약액 18,500원을 얻었어요.",
  "challenges": [
    {
      "challengeId": 31,
      "status": "SUCCESS",
      "estimatedSavingAmount": 5500,
      "message": "커피 한 잔만 줄이기 성공!"
    }
  ]
}
```

`successfulSavingAmount`는 해당 주에 현재까지 `SUCCESS`로 확정된 모든 챌린지의 `estimated_saving_amount` 합계다.

## 5. 투자효과의 `절약액` 카테고리

### 5.1 화면 구성

투자효과 페이지의 기존 소비 카테고리 탭에 `절약액`을 추가한다.

```text
절약액 | 카페·간식 | 식비 | 배달 | 교통 | 쇼핑 | 구독 | 전체
```

- 프론트엔드 카테고리 값은 `savings`를 사용한다.
- 기본 선택값은 기존 `coffee`를 유지한다.
- 챌린지 성공 화면에서 투자효과로 이동하는 기능을 추가할 경우에는 `savings`를 선택한 상태로 진입할 수 있다.
- 기존 소비 카테고리 선택 시에는 현재 동작을 그대로 유지한다.

### 5.2 월별 절약액 산정 기준

선택한 월에 `SUCCESS`로 완료된 챌린지의 `estimated_saving_amount`를 합산한다.

```text
월 예상 절약액
= 선택 월에 completed_at이 포함된 SUCCESS 챌린지의
  estimated_saving_amount 합계
```

- 월 경계는 `Asia/Seoul` 기준으로 계산한다.
- 주 시작일이 이전 달이어도 성공 완료 시각이 선택 월에 속하면 선택 월의 절약액에 포함한다.
- `FAIL`, `IN_PROGRESS` 챌린지는 포함하지 않는다.
- 동일 챌린지는 한 번만 포함한다.
- 포인트는 절약액에 포함하지 않는다.
- AI 채팅으로 추가된 챌린지도 동일한 기준으로 포함한다.

`estimated_saving_amount`는 기존 챌린지 레코드에 이미 저장되므로 별도 절약액 원장 테이블은 이번 프로토타입 범위에서 추가하지 않는다.

### 5.3 절약액 시뮬레이션

`category=savings`일 때 기존 소비 거래 합계 대신 월 예상 절약액을 투자 원금으로 사용한다. 자산별 시뮬레이션 계산식, 기준 매수일, 시세 데이터, 기본 비교 자산은 기존 투자효과 로직을 그대로 사용한다.

- 투자 원금: 선택 월의 예상 절약액 합계
- 기준 매수일: 선택 월의 첫 거래일
- 기본 비교군: S&P500 ETF, KOSPI 200 ETF, 정기예금/CMA
- 사용자 선택 종목: 기존 검색 및 비교 기능 유지

화면 문구 예시:

```text
7월 챌린지로 만든 예상 절약액
18,500원

이 절약액을 7월 첫 거래일에 투자했다면
현재 가치가 어떻게 달라졌을지 계산했어요.
```

기존 `소비한 돈`, `소비액` 문구를 그대로 사용하지 않고 `챌린지로 만든 예상 절약액`으로 구분한다.

### 5.4 API 확장

기존 API를 확장한다.

```http
GET /api/users/me/investment-effect/simulation
  ?category=savings
  &month=2026-07
  &assetCodes=005930
```

응답 예시:

```json
{
  "month": "2026-07",
  "category": "savings",
  "categoryLabel": "절약액",
  "spendingAmount": 0,
  "savedAmount": 18500,
  "investmentAmount": 18500,
  "amountSource": "CHALLENGE_ESTIMATED_SAVINGS",
  "savedAmountSource": "CHALLENGE_ESTIMATED_SAVINGS",
  "assumedBuyDate": "2026-07-01",
  "summaryText": "7월 챌린지로 만든 예상 절약액 18,500원을 기준으로 계산했어요.",
  "assumptionText": "이 절약액을 7월 첫 거래일에 투자했다면 현재 얼마인지 계산했어요.",
  "benchmarks": [],
  "comparisons": [],
  "status": "OK",
  "disclaimer": "투자 권유가 아닌 참고용 시뮬레이션입니다."
}
```

소비 카테고리 응답은 기존과 같이 `spendingAmount`와 `CATEGORY_SPENDING_AMOUNT` 출처를 사용한다. 절약액 응답은 `savedAmount`와 `CHALLENGE_ESTIMATED_SAVINGS` 출처를 사용해 화면에서 문구를 정확히 분기할 수 있게 한다.

### 5.5 절약액이 없는 경우

선택 월에 성공한 챌린지가 없거나 예상 절약액 합계가 0원이면 정상 응답으로 처리한다.

```json
{
  "month": "2026-07",
  "category": "savings",
  "categoryLabel": "절약액",
  "spendingAmount": 0,
  "savedAmount": 0,
  "investmentAmount": 0,
  "amountSource": "CHALLENGE_ESTIMATED_SAVINGS",
  "benchmarks": [],
  "comparisons": [],
  "status": "NO_SAVINGS",
  "summaryText": "7월에 인증된 챌린지 절약액이 아직 없어요.",
  "disclaimer": "투자 권유가 아닌 참고용 시뮬레이션입니다."
}
```

화면에서는 오류 대신 다음 빈 상태를 표시한다.

```text
이번 달에 모인 예상 절약액이 아직 없어요.
챌린지를 인증하면 절약액의 투자효과를 확인할 수 있어요.

[챌린지 보러 가기]
```

## 6. 사용자 흐름

### 챌린지 인증

```text
/challenge 진입
→ 미인증 챌린지 확인
→ 시간 제한 없이 '인증하기'
→ 랜덤 판정 로딩
→ 성공/미완료 카드 반영
→ 포인트와 예상 절약액 결과 표시
→ 성공 시 컨페티
```

### 절약액 투자효과

```text
/investment-effect 진입
→ 조회 연월 선택
→ '절약액' 탭 선택
→ 해당 월 성공 챌린지의 예상 절약액 합산
→ 기본 비교 자산 및 선택 종목 시뮬레이션
```

챌린지 성공 결과에는 다음 CTA를 제공한다.

```text
예상 절약액 18,500원을 얻었어요
→ [절약액 투자효과 보기]
→ /investment-effect?category=savings&month=2026-07
```

사용자가 CTA를 직접 눌렀을 때만 투자효과로 이동한다. 성공 직후 자동으로 화면을 전환하지 않는다.

## 7. 데이터 정합성 및 안전장치

- 랜덤 결과는 서버에서 생성하고 즉시 DB에 저장한다.
- 프론트엔드가 성공 개수나 절약액을 요청값으로 전달하지 않는다.
- 성공 챌린지 포인트는 기존 원장의 유니크 제약을 사용해 중복 지급을 방지한다.
- 월 절약액은 API 요청 시 DB의 `SUCCESS` 챌린지를 집계하며 클라이언트가 전달한 금액을 신뢰하지 않는다.
- 절약액 합계와 투자 계산에는 0 이상의 정수 금액만 사용한다.
- 투자효과 화면에는 기존 참고용 시뮬레이션 고지를 유지한다.
- 랜덤 판정은 프로토타입용이며 실제 성취를 검증한 결과처럼 표현하지 않는다. 필요하면 결과 화면에 `프로토타입 체험 결과`라는 보조 문구를 표시한다.

## 8. 구현 대상

### 프론트엔드

- 챌린지 화면의 시간 제한 안내 제거
- 챌린지가 미인증 상태면 `인증하기` 활성화
- 인증 결과에 `successfulSavingAmount` 표시
- 성공 결과에 `투자효과 보기` CTA를 표시하고 `savings` 카테고리와 완료 월을 전달
- 투자효과 카테고리 옵션에 `{ value: 'savings', label: '절약액' }` 추가
- `savings` 응답일 때 소비액 문구와 절약액 문구 분기
- `NO_SAVINGS` 빈 상태 및 챌린지 이동 CTA 처리

### 백엔드

- 챌린지 인증 가능 시간 검사 제거
- `IN_PROGRESS` 챌린지 대상 랜덤 성공/실패 판정 추가
- 인증 응답에 `successfulSavingAmount`, 챌린지별 `estimatedSavingAmount` 추가
- 투자효과 카테고리 매핑에 `savings: '절약액'` 추가
- 선택 월의 성공 챌린지 예상 절약액 집계 함수 추가
- `category=savings`일 때 투자 원금과 응답 문구 분기
- `NO_SAVINGS` 상태 추가

## 9. 완료 조건

- [ ] 요일과 시각에 관계없이 미인증 챌린지가 있으면 `인증하기`가 활성화된다.
- [ ] 기존 인증 가능 시각 안내가 챌린지 화면에서 제거된다.
- [ ] 인증 시 서버가 미인증 챌린지 중 최소 1개 이상을 무작위로 성공 처리한다.
- [ ] 인증 결과가 DB에 저장되어 새로고침과 재요청에도 바뀌지 않는다.
- [ ] 성공 챌린지별 포인트가 한 번만 지급된다.
- [ ] 인증 결과에 성공 챌린지의 예상 절약액 합계가 표시된다.
- [ ] 성공 결과의 `투자효과 보기`를 누르면 해당 월 `절약액` 카테고리로 이동한다.
- [ ] 투자효과 카테고리 목록에 `절약액`이 표시된다.
- [ ] `절약액` 선택 시 선택 월에 성공 완료된 챌린지의 예상 절약액만 합산한다.
- [ ] 절약액을 원금으로 기본 비교 자산과 선택 종목의 투자효과를 계산한다.
- [ ] 절약액이 0원이면 오류가 아니라 `NO_SAVINGS` 빈 상태를 표시한다.
- [ ] 기존 소비 카테고리 투자효과 동작은 변경되지 않는다.
- [ ] 투자 권유가 아닌 참고용 시뮬레이션 고지를 유지한다.

## 10. 검증 시나리오

1. 월요일에 챌린지 화면에 진입해도 `인증하기` 버튼이 활성화되는지 확인한다.
2. 챌린지 5개를 인증했을 때 1~5개가 성공하고 나머지가 실패하는지 확인한다.
3. 성공 결과의 포인트와 예상 절약액이 성공 챌린지 합계와 일치하는지 확인한다.
4. 같은 인증 API를 반복 호출해 결과와 포인트가 바뀌지 않는지 확인한다.
5. 인증 완료 후 새 챌린지를 추가하고 다시 인증했을 때 새 챌린지만 판정되는지 확인한다.
6. 투자효과에서 `절약액`을 선택하면 해당 월 성공 챌린지만 합산되는지 확인한다.
7. 월 경계에 완료된 챌린지가 KST 기준 올바른 월에 포함되는지 확인한다.
8. `FAIL`, `IN_PROGRESS`, 예상 절약액 0원 챌린지가 합계에 영향을 주지 않는지 확인한다.
9. 성공 챌린지가 없는 월에 `NO_SAVINGS` 상태와 챌린지 CTA가 표시되는지 확인한다.
10. 카페·간식 등 기존 소비 카테고리의 계산 결과가 이전과 동일한지 확인한다.
11. 프론트엔드에서 `npm run lint`, `npm run build`를 실행한다.
12. 백엔드에서 인증 API와 투자효과 API를 직접 호출하고 JSON 응답을 확인한다.
