# AI 주간 절약 챌린지

## 1. 목적과 범위

사용자의 최근 거래내역을 바탕으로 AI가 한 주 동안 함께 수행할 맞춤형 절약 미션을 생성한다. 기본 추천 미션을 제공하고 AI 채팅에서도 새 미션을 추가할 수 있으며, 모든 미션은 월요일부터 금요일까지 동시에 진행한다.

MVP 범위는 다음과 같다.

- 매주 월요일 사용자별 기본 주간 미션을 생성해 DB에 저장한다.
- 미션은 직전 주를 우선으로 한 최근 거래내역의 결제 횟수와 금액을 근거로 만든다.
- 화면에는 이번 주 미션 전체와 수행 기간, 인증 가능 시각을 표시한다.
- 토요일 00:00 KST부터 `인증하기` 버튼을 활성화한다.
- 한 번의 인증 요청으로 수행 기간 전체 거래내역을 조회해 모든 미션을 일괄 판정한다.
- 성공 미션이 하나 이상이면 결과 화면에 컨페티 효과를 재생한다.
- 성공 미션별 포인트를 지급하고 랭킹에서 읽을 수 있게 한다.

영수증 업로드, 사진 OCR, 자기 신고 방식은 제외한다. 거래내역으로 자동 판정할 수 있는 미션만 생성하며, 저장된 미션은 새로고침이나 재로그인 후에도 유지한다.

---

## 2. 주간 정책

- 한 주의 수행 기간은 월요일 `00:00:00` 이상 토요일 `00:00:00` 미만이다.
- 월요일에 현재 주 기본 미션을 한 번 생성한다.
- 생성 스케줄러가 누락된 경우 현재 주 첫 조회에서 같은 생성 서비스를 호출한다.
- 화~금에 처음 생성되거나 채팅에서 추가된 미션도 남은 주간 동안 수행하며, 이미 지난 요일을 이유로 실패 처리하지 않는다.
- 토요일 `00:00:00`부터 다음 주 월요일 `00:00:00` 직전까지 인증할 수 있다.
- 인증 기간이 끝날 때까지 인증하지 않은 미션은 `FAIL`로 마감한다.
- 모든 시간 계산은 `Asia/Seoul`을 기준으로 한다.

## 3. 화면 요구사항

### 3.1 상단과 요약

- 제목: `챌린지`
- 설명: `지난 소비를 살펴보고, 이번 주에 도전할 맞춤 미션을 준비했어요.`
- 수행 기간과 `성공 개수/전체 개수` 진행 요약을 표시한다.
- 수행 중에는 `이번 주 미션을 함께 진행하고 있어요`를 표시한다.

### 3.2 이번 주 미션

- 전체 미션을 동일한 주간 미션으로 표시하며 요일을 배정하지 않는다.
- AI 채팅에서 추가된 미션은 `방금 추가됨` 배지와 일시적인 강조 효과로 식별한다.
- 각 항목은 카테고리, 거래내역 근거와 이번 주 목표를 합친 단일 문장, 예상 절약액을 가진다. 별도의 제목과 유사한 설명을 반복하지 않는다.
- 금액형 미션의 현재 상태는 `현재 12,340원 / 목표 20,000원`처럼 이번 주 실제 거래 합계와 목표 금액을 정확히 함께 표시한다. 횟수형은 `현재 1번 / 목표 2번`으로 표시한다.
- `진행중` 상태는 표시하지 않는다. `성공`과 `미완료`는 사용자가 `인증하기`를 눌러 판정이 끝난 뒤에만 표시한다.
- 생성되지 않은 경우 `이번 주 미션을 준비하고 있어요.`를 표시한다.
- 미션 문구는 사용자를 비난하거나 과소비로 단정하지 않고 가벼운 제안형 어조를 사용한다.

문구 예시:

- `지난 주에는 커피를 3잔 마셨네요. 이번 주에는 커피를 2잔으로 줄여볼까요?`
- `저번 주 배달 주문이 2번 있었어요. 이번 주에는 한 번만 주문해보는 건 어때요?`
- `지난 7일 동안 편의점에서 24,000원을 썼어요. 이번 주에는 20,000원 안에서 알차게 골라봐요.`
- `저번 주 택시비가 32,000원이었어요. 이번 주에는 25,000원까지 천천히 줄여봐요.`
- `지난주 쇼핑 결제가 4번 있었어요. 이번 주에는 3번까지만 즐겨볼까요?`

### 3.3 인증 CTA와 성공 연출

- 금요일까지 `인증하기` 버튼은 비활성화한다.
- 비활성 상태에는 `토요일 00:00부터 인증할 수 있어요`를 표시한다.
- 토요일 00:00 KST부터 버튼을 활성화한다.
- 클릭 시 이번 주 전체 미션을 한 번에 인증하며, 처리 중에는 중복 요청을 막고 거래내역 확인 오버레이를 표시한다.
- 인증 후 `성공 개수/전체 개수`, 획득 포인트, 미션별 성공·실패 결과를 표시한다.
- 성공 미션이 하나 이상이면 컨페티를 2~3초 동안 한 번만 재생한다.
- `prefers-reduced-motion: reduce`에서는 컨페티를 생략하고 정적인 성공 메시지를 제공한다.

### 3.4 접근 제어

- 로그인 사용자만 조회·인증할 수 있다.
- 거래내역이 없는 사용자는 챌린지 대신 마이데이터 연결 안내를 받는다.
- 하단 탭의 `/challenge`를 활성화하고 플로팅 챗봇 버튼은 `/coach`로 이동한다.

## 4. AI 생성 규칙

### 4.1 생성 시점과 멱등성

- 매주 월요일 00:10 KST 스케줄러가 대상 사용자별 기본 미션을 생성한다.
- `GET /api/users/me/challenges`는 현재 주 미션이 없을 때 동일 생성 서비스를 호출해 누락을 보완한다.
- `(user_id, week_start_date, sequence)` 유니크 제약으로 순서 중복을 막는다. 한 주의 미션 총개수에는 고정 상한을 두지 않는다.
- 같은 주의 조회, 새로고침, 재로그인에서는 AI를 다시 호출하지 않는다.

### 4.2 거래내역 컨텍스트

1. 직전 주 월요일 00:00 이상 현재 주 월요일 00:00 미만의 거래를 우선 분석한다.
2. 직전 주 데이터가 부족하면 최근 30일까지 범위를 확장하되, 문구의 기준 기간을 `최근 30일`처럼 정확히 표현한다.
3. 카테고리별 결제 횟수, 총액, 평균 결제금액과 반복 가맹점 정보를 AI에 제공한다.
4. 사용자가 선택한 관심 카테고리가 있으면 우선 사용하고, 부족하면 거래가 있는 다른 카테고리로 채운다.
5. 거래가 있는 카테고리를 순환해 필요한 수만큼 배정한다. 같은 카테고리를 다시 사용하면 목표 지표나 미션 유형을 다르게 한다.
6. 거래가 전혀 없으면 미션을 생성하지 않고 마이데이터 연결 필요 상태를 반환한다.

### 4.3 지원 미션 유형

거래내역만으로 판정할 수 있도록 다음 유형을 허용한다.

| 유형 | 의미 | 성공 조건 |
|---|---|---|
| `MAX_COUNT` | 특정 카테고리 결제 횟수 줄이기 | 주간 결제 건수가 `targetCount` 이하 |
| `MAX_SPEND` | 특정 카테고리 지출 한도 지키기 | 주간 지출 합계가 `targetAmount` 이하 |
| `NO_SPEND` | 특정 카테고리 무지출 | 주간 결제 건수가 0 |

`택시 대신 지하철`, `요금제 점검`, `영수증 인증`처럼 거래내역만으로 행동을 확인할 수 없는 목표는 생성하지 않는다.

### 4.4 AI 출력 형식과 문구

```json
{
  "challenges": [
    {
      "sequence": 1,
      "expenseCategoryName": "카페·간식",
      "challengeType": "MAX_COUNT",
      "title": "커피 한 잔만 가볍게 줄이기",
      "description": "저번 주에는 커피를 3잔 마셨어요. 이번 주에는 2잔으로 가볍게 줄여볼까요?",
      "baselinePeriod": "2026-07-20/2026-07-26",
      "baselineCount": 3,
      "baselineAmount": 16500,
      "targetCount": 2,
      "targetAmount": null,
      "estimatedSavingAmount": 5500,
      "difficulty": "HARD",
      "point": 150
    }
  ]
}
```

- 현재 주에 저장된 미션 전체를 반환한다.
- 설명에는 기준 기간의 실제 결제 횟수 또는 금액과 이번 주 목표를 함께 넣는다.
- `저번 주에는 …했어요. 이번 주에는 …해볼까요?`처럼 친근하고 판단하지 않는 어조를 사용한다.
- 서버가 제공하지 않은 거래 사실, 금액, 횟수, 가맹점을 만들어내지 않는다.
- 목표는 기준값보다 낮고 0 이상이어야 하며 지나치게 공격적인 감축을 피한다.
- `point`는 미션 난이도에 따라 50포인트 단위로 산정한다.
- 서버는 스키마, 카테고리, 기준값, 목표값을 검증하고 오류 시 최대 1회 재요청한다.
- 모델은 `OPENAI_MODEL`, 키는 `OPEN_AI_KEY` 환경변수에서 읽는다.

### 4.5 난이도와 포인트

난이도는 사용자의 기준 소비 대비 목표 감축률로 결정한다.

| 난이도 | 기준 | 포인트 |
|---|---|---:|
| `EASY` | 감축률 20% 이하 | 50P |
| `MEDIUM` | 감축률 20% 초과, 40% 이하 | 100P |
| `HARD` | 감축률 40% 초과 | 150P |

- `MAX_COUNT` 감축률: `(기준 횟수 - 목표 횟수) / 기준 횟수 × 100`
- `MAX_SPEND` 감축률: `(기준 금액 - 목표 금액) / 기준 금액 × 100`
- `NO_SPEND`는 기준 기간 거래가 1회면 `MEDIUM`, 2회 이상이면 반복 습관을 완전히 쉬어야 하므로 `HARD`로 정한다.
- 현재 주의 미인증 미션은 조회 시 이 기준으로 포인트를 보정한다.
- 이미 인증되어 지급된 과거 포인트는 원장 정합성을 위해 다시 계산하지 않는다.

## 5. 데이터 모델

주간 미션을 위해 `ai_challenge`에 다음 정보를 저장한다.

| 컬럼 | 타입/제약 | 설명 |
|---|---|---|
| `week_start_date` | `DATE NOT NULL` | 수행 주의 월요일 |
| `sequence` | `TINYINT NOT NULL` | 주간 목록 순서 1~5 |
| `expense_category_id` | `BIGINT NOT NULL`, FK | 대상 카테고리 |
| `challenge_type` | `ENUM('NO_SPEND','MAX_SPEND','MAX_COUNT') NOT NULL` | 자동 판정 방식 |
| `baseline_period_start` | `DATE NOT NULL` | 문구 근거 기간 시작 |
| `baseline_period_end` | `DATE NOT NULL` | 문구 근거 기간 종료 |
| `baseline_count` | `INT NOT NULL DEFAULT 0` | 근거 결제 횟수 |
| `baseline_amount` | `BIGINT NOT NULL DEFAULT 0` | 근거 지출 합계 |
| `target_count` | `INT NULL` | `MAX_COUNT` 목표 횟수 |
| `target_amount` | `BIGINT NULL` | `MAX_SPEND` 목표 금액 |
| `estimated_saving_amount` | `BIGINT NOT NULL DEFAULT 0` | 예상 절약액 |
| `completed_at` | `DATETIME NULL` | 판정 완료 시각 |
| `rewarded_at` | `DATETIME NULL` | 포인트 지급 시각 |

필수 제약:

```text
UNIQUE (user_id, week_start_date, sequence)
INDEX  (user_id, week_start_date, status)
CHECK  (sequence BETWEEN 1 AND 5)
CHECK  (point >= 0)
```

상태는 `IN_PROGRESS`, `SUCCESS`, `FAIL`만 사용한다. 성공 미션별 포인트 지급과 상태 변경은 하나의 DB 트랜잭션으로 처리한다.

## 6. API 계약

### 6.1 주간 챌린지 조회

`GET /api/users/me/challenges?week=YYYY-MM-DD`

- `week`가 없으면 현재 주를 반환한다.
- `week`가 있으면 해당 날짜가 포함된 주를 반환한다.
- 현재 주 데이터가 없으면 기본 미션을 생성해 저장한 뒤 반환한다.

```json
{
  "weekStartDate": "2026-07-27",
  "weekEndDate": "2026-07-31",
  "verificationOpensAt": "2026-08-01T00:00:00+09:00",
  "verificationClosesAt": "2026-08-03T00:00:00+09:00",
  "canVerify": false,
  "onboardingRequired": false,
  "successfulCount": 0,
  "totalCount": 5,
  "weeklyChallenges": [
    {
      "id": 31,
      "sequence": 1,
      "category": "카페·간식",
      "title": "커피 한 잔만 가볍게 줄이기",
      "description": "저번 주에는 커피를 3잔 마셨어요. 이번 주에는 2잔으로 가볍게 줄여볼까요?",
      "challengeType": "MAX_COUNT",
      "targetCount": 2,
      "estimatedSavingAmount": 5500,
      "difficulty": "HARD",
      "point": 150,
      "status": "IN_PROGRESS"
    }
  ]
}
```

### 6.2 주간 일괄 인증

`POST /api/users/me/challenges/verify`

- 토요일 00:00 KST부터 다음 주 월요일 00:00 직전까지만 허용한다.
- 현재 주의 모든 미션을 월~금 전체 거래내역으로 일괄 판정한다.
- 인증 및 보상 규칙은 `ai-challenge-verification.md`를 따른다.

## 7. 완료 조건

- [ ] 사용자별 기본 주간 미션이 생성되고 채팅으로 추가된 미션도 모두 월~금 동안 함께 진행된다.
- [ ] 미션은 실제 거래내역의 기간·횟수·금액을 근거로 하며 친근한 제안형 문구를 사용한다.
- [ ] `NO_SPEND`, `MAX_SPEND`, `MAX_COUNT` 미션을 거래내역만으로 판정할 수 있다.
- [ ] 토요일 00:00 KST 전에는 인증 버튼이 비활성화되고 이후 활성화된다.
- [ ] 한 번의 인증 요청으로 이번 주 전체 미션의 결과와 포인트가 확정된다.
- [ ] 난이도가 감축률에 따라 `EASY`/`MEDIUM`/`HARD`로 분류되고 50P/100P/150P가 지급된다.
- [ ] 성공 미션이 하나 이상이면 컨페티가 한 번 재생되고 모션 감소 설정을 존중한다.
- [ ] 재인증, 동시 요청, 새로고침에도 포인트가 중복 지급되거나 컨페티가 반복 재생되지 않는다.
- [ ] 단위 테스트에 주간 중복 생성, 거래 근거 검증, 토요일 00:00 경계, 일괄 판정, 만료, 포인트 멱등성을 포함한다.
