# 투자효과 페이지 (Investment Effect)

## 페이지 개요

투자효과 페이지는 사용자가 특정 월/카테고리에서 실제로 소비한 금액을 지수 ETF 또는 사용자가 직접 검색한 주식에 배분했다고 가정했을 때의 기회비용과 현재 평가 금액을 보여주는 참고용 시뮬레이션 화면이다.

이 화면은 실제 투자 주문, 금융상품 가입, 종목 추천을 제공하지 않는다. 목적은 `내가 쓴 돈을 투자했다면 어떤 기회비용이 있었는지`를 숫자로 보여주어 소비 패턴을 돌아보게 만드는 것이다.

기본 화면은 특정 브랜드 주식을 전면에 내세우지 않고 `S&P500 ETF`, `KOSPI 200 ETF`, `정기예금/CMA`처럼 넓은 시장 지수 또는 안정형 비교군을 우선 보여준다. 개별 주식은 사용자가 검색해서 선택했을 때만 `그때 샀다면 지금 얼마나 달라졌을까`를 확인하는 보조 흐름으로 제공한다.

- Figma 와이어프레임: https://www.figma.com/design/097N3w8EmKyENAmjkQO3q4/Kopilot?node-id=81-4&m=dev
- 라우트: `/investment-effect`
- 하단 탭: `투자효과` 활성화
- 고지 문구: `투자효과는 투자 권유가 아닌 참고용 시뮬레이션입니다.`

---

## 핵심 기대 효과

사용자는 이 페이지에서 다음을 확인할 수 있어야 한다.

1. 선택한 월/카테고리에서 실제로 사용한 금액
2. 그 소비 금액을 대표 지수 ETF에 투자했다고 가정했을 때의 현재 평가 금액
3. 원금 대비 예상 손익 금액과 수익률
4. 주식/ETF처럼 변동성이 있는 자산과 정기예금처럼 안정적인 비교군의 차이
5. 사용자가 직접 검색한 주식을 샀다면 현재 평가 금액이 어떻게 달라졌는지
6. 투자 결과가 손실일 수 있으며, 시뮬레이션이 투자 권유가 아니라는 사실

예시 문구:

```text
2026년 7월 카페·간식 소비액 60,000원
이 돈을 S&P500 ETF에 투자했다면 현재 약 65,100원이 되었어요.
```

## 화면 구성

### 1. 상단 타이틀 영역

- 타이틀: `투자효과`
- 서브타이틀: `소비한 돈의 기회비용을 참고용 시뮬레이션으로 확인해요.`
- 보조 안내: `지수 ETF와 관심 종목을 기준으로 참고용 투자효과를 계산해요.`

### 2. 소비액 요약 카드

사용자가 선택한 월/카테고리에서 실제로 사용한 금액을 가장 먼저 강조한다.

- 표시 금액: `2026년 7월 카페·간식 소비액 60,000원`
- 산출 기준: `transaction_history`의 해당 월/카테고리 실제 결제 금액 합계
- 기본 카테고리: `coffee`
- 카테고리 변경 옵션: 카페·간식, 식비, 배달, 교통, 쇼핑, 구독, 전체

### 3. 월 선택 기준

투자효과는 소비가 발생한 월과 투자 가정 월을 반드시 동일하게 묶는다.

- `2026년 6월` 소비액 조회: `2026년 6월에 해당 자산을 샀다면?`으로 계산
- `2026년 7월` 소비액 조회: `2026년 7월에 해당 자산을 샀다면?`으로 계산

화면에는 브라우저 또는 OS 기본 월 선택 캘린더를 제공한다.

- 기본값: 현재 월
- 선택 값 형식: `YYYY-MM`
- 월 변경 시 소비액, 기준 매수일, 수익률, 평가 금액을 모두 다시 계산한다.

선택 월의 투자 기준일은 해당 월의 첫 거래일을 기본으로 한다. 예를 들어 `2026-07`을 조회하면 `2026년 7월 첫 거래일에 샀다면` 현재 얼마인지 계산한다.

### 4. 기본 비교 자산 영역

사용자가 별도 검색을 하지 않아도 소비액의 투자효과를 빠르게 이해할 수 있도록 시장 대표 비교군을 먼저 보여준다.

- 기본 비교군:
  - `S&P500 ETF`
  - `KOSPI 200 ETF`
  - `정기예금` 또는 `CMA`
- 기본 비교군 선정 원칙:
  - 개별 회사가 아니라 시장 대표 지수 또는 안정형 자산을 우선한다.
  - 특정 종목 매수 권유처럼 보이는 표현을 피한다.
  - 변동성이 있는 ETF와 안정형 비교군을 함께 보여준다.

주가가 하락한 경우에도 절약 동기부여가 지나치게 약해지지 않도록, 기본 화면에는 안정적인 비교군인 `정기예금` 또는 `CMA`를 항상 포함한다.

### 5. 종목 검색 영역

사용자가 궁금한 주식이나 ETF를 직접 검색해 `그때 샀다면 지금 얼마나 올랐거나 내렸는지`를 확인할 수 있게 한다.

- 검색 입력 플레이스홀더: `궁금한 주식이나 ETF를 검색해보세요`
- 검색 대상:
  - 국내 주식
  - 국내 ETF
  - 해외 주식 또는 해외 ETF는 CHECK API 계약 범위에서 지원 가능한 경우만 노출
- 검색 결과 표시 정보:
  - 종목명
  - 종목 코드
  - 자산 유형: 주식, ETF
  - 시장: KOSPI, KOSDAQ, ETF 등
  - 현재가
  - 등락률
- 선택 후 동작:
  - 선택한 종목을 기본 비교 결과 아래에 `내가 고른 종목` 카드로 표시한다.
  - 이미 선택한 종목이 있으면 새 종목 카드로 대체한다.
  - `선택한 월 소비액을 이 종목에 투자했다면`이라는 문구로 표시한다.
  - 기본 비교군과 동일한 계산식으로 평가 금액과 손익을 표시한다.

개별 주식 검색은 사용자의 호기심을 해소하는 기능이지 추천 기능이 아니다. 따라서 `추천 종목`, `인기 종목 사기`, `매수하기` 같은 문구와 CTA는 사용하지 않는다.

### 6. 시뮬레이션 결과 카드

각 비교 대상별로 다음 값을 표시한다.

- 비교 대상명
- 현재가 또는 적용 이율
- 기준 매수일
- 기준일 가격
- 기준 수익률
- 투자 가정 원금
- 현재 평가 금액
- 예상 손익
- 손익률
- 시세 기준 시각

예시:

```json
{
  "label": "S&P500 ETF",
  "assetType": "ETF",
  "investmentAmount": 60000,
  "assumedBuyDate": "2026-07-01",
  "basePrice": 60100,
  "currentPrice": 65200,
  "returnRate": 0.085,
  "estimatedValue": 65100,
  "estimatedGain": 5100,
  "quotedAt": "2026-07-26T15:00:00+09:00"
}
```

### 7. 하단 고지

화면 하단 또는 결과 카드 하단에 다음 내용을 명확히 표시한다.

```text
본 화면은 소비액의 기회비용을 이해하기 위한 참고용 시뮬레이션입니다.
투자 권유 또는 금융상품 추천이 아니며, 과거 수익률은 미래 수익을 보장하지 않습니다.
```

## 사용하는 API

투자효과 페이지는 프론트엔드에서 코스콤 CHECK API를 직접 호출하지 않는다. `cust_id`와 `auth_key`가 외부에 노출되지 않도록 백엔드가 코스콤 CHECK API를 호출하고, 프론트엔드는 Kopilot 백엔드 API만 호출한다.

### 1. 프론트엔드 호출 API

#### `GET /api/users/me/investment-effect/simulation?category=coffee`

현재 로그인한 사용자의 월별 카테고리 소비액, 기본 지수 ETF 비교 결과, 사용자가 선택한 종목의 시뮬레이션 결과를 조회한다.

요청 파라미터:

| 이름 | 위치 | 필수 | 설명 |
| --- | --- | --- | --- |
| `category` | query | 선택 | 시뮬레이션 기준 소비 카테고리. 기본값은 `coffee` |
| `month` | query | 선택 | 조회 월. 형식은 `YYYY-MM`, 기본값은 현재 월. 해당 월의 소비액과 해당 월 첫 거래일 매수 가정을 함께 결정한다. |
| `assetCodes` | query | 선택 | 사용자가 직접 검색 후 선택한 비교 자산 코드 목록. 쉼표로 구분 |
| `benchmark` | query | 선택 | 기본 비교군 묶음. 기본값은 `index-etf` |

#### `GET /api/investment/assets/search`

사용자가 입력한 검색어에 맞는 주식 또는 ETF 후보를 조회한다. 프론트에서 종목 검색 UI를 만들 때 사용한다. 검색은 매 요청마다 코스콤 마스터 API를 직접 훑지 않고, 백엔드 DB의 `investment_asset` 종목 마스터 테이블을 기준으로 수행한다. DB가 비어 있으면 최초 검색 또는 수동 동기화 시 코스콤 CHECK API 마스터를 적재한다.

요청 파라미터:

| 이름 | 위치 | 필수 | 설명 |
| --- | --- | --- | --- |
| `keyword` | query | 필수 | 종목명 또는 종목 코드 검색어 |
| `type` | query | 선택 | `stock`, `etf` 중 하나 |
| `market` | query | 선택 | `kospi`, `kosdaq`, `etf` 등 시장 필터 |
| `limit` | query | 선택 | 응답 개수. 기본값 `20` |

응답 예시:

```json
{
  "items": [
    {
      "assetCode": "005930",
      "label": "삼성전자",
      "assetType": "STOCK",
      "market": "KOSPI",
      "description": "국내 주식",
      "source": "KOSCOM_CHECK_DB"
    }
  ]
}
```

#### `GET /api/investment/quotes`

선택된 시뮬레이션 대상 자산의 현재 시세, 종목명, 등락률을 조회한다. 가격 데이터는 `investment_price` 테이블의 최신 종가를 우선 사용하고, 저장된 가격이 없을 때만 코스콤 CHECK API의 기본 시세를 호출해 DB에 저장한다.

#### `POST /api/investment/sync`

코스콤 CHECK API 데이터를 수동 동기화한다. 운영 스케줄러와 동일한 로직을 사용하며, 로컬 검증이나 배포 직후 초기 적재에 사용한다.

요청 파라미터:

| 이름 | 위치 | 필수 | 설명 |
| --- | --- | --- | --- |
| `mode` | query/body | 선택 | `all`이면 종목 마스터와 가격을 모두 동기화한다. `prices`이면 가격만 동기화한다. 기본값은 `all` |
| `limit` | query/body | 선택 | 가격 동기화 대상 최대 개수. 기본값은 `KOSCOM_PRICE_SYNC_LIMIT` 또는 `200` |

## 코스콤 CHECK API 연동

백엔드는 아래 CHECK API를 사용해 시뮬레이션에 필요한 자산 코드와 시세를 조회한다.

### 1. 주식 종목 마스터 조회

```text
POST https://checkapi.koscom.co.kr/stock/m001/code_info
```

용도:

- 주식 종목 코드와 종목명을 조회한다.
- 사용자가 개별 주식을 검색할 때 사용한다.

### 2. ETF 종목 마스터 조회

```text
POST https://checkapi.koscom.co.kr/stock/m001/code_etf_info
```

용도:

- ETF 코드와 ETF명을 조회한다.
- `S&P500 ETF`, `KOSPI 200 ETF` 같은 기본 비교군 또는 사용자가 선택한 ETF를 매핑할 때 사용한다.

### 3. 기본 시세 조회

```text
POST https://checkapi.koscom.co.kr/stock/m001/basic_info
```

용도:

- 선택된 주식 또는 ETF의 현재가(`F15001`)와 등락률(`F15004`)을 조회한다.
- 시뮬레이션 카드의 현재가, 수익률, 기준 시각을 구성한다.

예상 요청 파라미터:

| 이름 | 필수 | 설명 |
| --- | --- | --- |
| `cust_id` | 필수 | 코스콤 CHECK API 고객 식별자. 백엔드 환경 변수 `CUST_ID`에서 읽어 POST body에 담는다. |
| `auth_key` | 필수 | 코스콤 CHECK API 인증 키. 백엔드 환경 변수 `AUTH_KEY`에서 읽어 POST body에 담는다. |
| `jcode` | 필수 | 조회할 종목 단축코드 6자리. 예: `005930` |
| `data_list` | 선택 | 조회 필드 목록. 예: `F16013,F16002,F15001,F15004` |

> 실제 CHECK API 파라미터명과 응답 필드는 계약 명세서 버전에 따라 달라질 수 있으므로, 구현 시 코스콤에서 제공받은 최신 명세를 기준으로 어댑터에서만 보정한다.

## 환경 변수 및 배포 설정

### 로컬 개발

백엔드 로컬 `.env` 파일에 다음 값을 추가한다.

```env
CUST_ID=발급받은_CHECK_API_고객_ID
AUTH_KEY=발급받은_CHECK_API_인증_KEY
```

프론트엔드 `.env`에는 `CUST_ID`, `AUTH_KEY`를 넣지 않는다. 브라우저 번들에 포함될 수 있으므로 반드시 백엔드에서만 사용한다.

### GitHub Actions 배포

배포 환경에서는 GitHub Actions에 다음 이름으로 값을 등록한다.

| 이름 | 권장 저장 위치 | 사용 위치 |
| --- | --- | --- |
| `CUST_ID` | Actions secret 권장 | 백엔드 컨테이너 환경 변수 |
| `AUTH_KEY` | Actions secret 권장 | 백엔드 컨테이너 환경 변수 |

`CUST_ID`와 `AUTH_KEY`는 코스콤 CHECK API 인증에 함께 사용되므로 일반 variable보다 secret으로 관리하는 것을 권장한다. 배포 워크플로우는 secret을 우선 사용하고, 아직 Actions variable에만 등록된 경우를 위해 variable fallback을 허용한다. 이 값은 백엔드 런타임 환경 변수로 전달해야 하며, 로그에 원문이 출력되면 안 된다.

## 시뮬레이션 계산 방식

### 1. 투자 원금 산출

투자 원금은 선택한 월/카테고리의 실제 소비액으로 계산한다.

1. `month=YYYY-MM`에 해당하는 `transaction_history`를 조회한다.
2. `category=coffee`이면 `카페·간식`, `delivery`이면 `배달`처럼 화면 카테고리를 DB 카테고리명으로 매핑한다.
3. `category=all`이면 해당 월 전체 소비액을 합산한다.
4. 소비 데이터가 없으면 mock 기본값을 사용하지 않고 `NO_SPENDING` 상태로 응답한다.

### 2. 투자효과 산출

기본 계산식:

```text
평가 금액 = 소비 금액 × (1 + 수익률)
예상 손익 = 평가 금액 - 소비 금액
손익률 = 예상 손익 / 소비 금액
```

코스콤 CHECK API에서 특정 기간 수익률을 직접 제공하지 않는 경우, 백엔드는 기준 시점 가격과 현재가를 활용해 수익률을 산출한다.

```text
수익률 = (현재가 - 기준가) / 기준가
```

월별 매수 가정 규칙:

- `month=2026-06`이면 `2026년 6월 소비액`을 사용하고, `2026년 6월 첫 거래일` 가격을 기준가로 사용한다.
- `month=2026-07`이면 `2026년 7월 소비액`을 사용하고, `2026년 7월 첫 거래일` 가격을 기준가로 사용한다.
- 선택 월의 1일이 휴장일이면 그 월의 첫 거래 가능일 가격을 사용한다.
- 사용자가 특정 챌린지 시작일 기준 보기를 선택한 경우에만 해당 시작일 가격을 기준가로 사용할 수 있다.
- 기준가 데이터가 DB에 없으면 mock 기준가를 사용하지 않고 `PRICE_HISTORY_MISSING` 오류를 반환한다. 운영에서는 매일 종가 동기화 스케줄러가 `investment_price`를 채우므로, 선택 월 첫 거래일 이후부터 실제 종가 기반 계산이 가능하다.
- 현재가 데이터가 없고 기준일 가격만 있는 경우 기준일 가격을 현재가로 재사용하지 않는다. 이 경우 `CURRENT_PRICE_MISSING` 오류를 반환해 0% 수익률처럼 보이는 잘못된 결과를 막는다.

예시:

```text
month=2026-06 선택 → 2026년 6월에 S&P500 ETF를 샀다면?
month=2026-07 선택 → 2026년 7월에 S&P500 ETF를 샀다면?
```

### 3. 검색 종목 투자효과 산출

사용자가 검색한 종목을 선택하면 백엔드는 선택 월의 소비액, 선택 월 첫 거래일의 기준가, 현재가를 조회해 평가 금액을 계산한다.

```text
선택 종목 평가 금액 = 소비 금액 × (1 + 선택 종목 수익률)
선택 종목 예상 손익 = 선택 종목 평가 금액 - 소비 금액
```

화면 문구는 다음처럼 표현한다.

```text
2026년 7월 카페·간식에 쓴 60,000원을 삼성전자에 투자했다면
현재 약 63,120원으로 계산돼요.
```

이 문구는 사용자가 직접 검색한 결과에만 표시하며, 기본 화면에서는 특정 개별 종목을 먼저 노출하지 않는다.

### 4. 정기예금 비교군

정기예금은 코스콤 CHECK API가 아니라 내부 고정 이율 테이블 또는 별도 금리 API를 사용한다.

MVP 기본값:

```json
{
  "assetCode": "TERM_DEPOSIT",
  "label": "정기예금",
  "assetType": "DEPOSIT",
  "annualInterestRate": 0.032
}
```

월 단위 단순 계산:

```text
예상 이자 = 소비 금액 × 연이율 × (보유 개월 수 / 12)
```

## 상태 및 예외 처리

### 1. 코스콤 CHECK API 인증값 누락

상황:

- `CUST_ID` 또는 `AUTH_KEY`가 백엔드 런타임 환경 변수에 없다.

백엔드 응답:

```json
{
  "code": "KOSCOM_CONFIG_MISSING",
  "message": "투자효과 시세 조회 설정이 아직 완료되지 않았습니다."
}
```

프론트 표시:

```text
시세 조회 설정이 아직 완료되지 않았어요.
잠시 후 다시 확인해주세요.
```

### 2. 코스콤 CHECK API 호출 실패

상황:

- 네트워크 오류
- 인증 실패
- 코스콤 API 장애
- 요청 제한 초과

처리:

- 백엔드는 실패 원문에 포함된 인증 키를 로그에 남기지 않는다.
- 최신 저장 종가가 있으면 해당 DB 데이터를 사용한다.
- 기준일 종가가 없으면 `PRICE_HISTORY_MISSING` 상태로 내려준다.

프론트 표시:

```text
일부 시세를 불러오지 못했어요.
가능한 비교 결과만 먼저 보여드릴게요.
```

### 3. 기준일 종가 없음

상황:

- 선택 월 첫 거래일의 종가가 `investment_price`에 아직 저장되지 않았다.
- 배포 직후라 매일 종가 스케줄러가 아직 충분한 기간 동안 실행되지 않았다.

백엔드 응답:

```json
{
  "code": "PRICE_HISTORY_MISSING",
  "message": "S&P500 ETF의 2026-07-01 종가가 DB에 없어 투자효과를 계산할 수 없습니다.",
  "meta": {
    "assetCode": "360750",
    "label": "S&P500 ETF",
    "tradeDate": "2026-07-01"
  }
}
```

프론트 표시:

```text
해당 월 기준 종가가 아직 DB에 없어요.
종가 동기화가 완료된 뒤 다시 확인해주세요.
```

### 4. 소비액이 0원 이하

상황:

- 선택한 월 또는 카테고리에 소비 내역이 없다.

프론트 표시:

```text
선택한 월에는 아직 시뮬레이션할 소비액이 없어요.
다른 월이나 카테고리를 선택해보세요.
```

이 경우 투자효과 결과 카드는 표시하지 않고, 챌린지 또는 예산 화면으로 이동하는 CTA를 제공한다.

### 5. 손실 결과

주식 또는 ETF 비교 결과가 손실이면 숨기지 않고 그대로 표시한다.

- 손실 금액 색상: 경고 또는 중립 색상
- 문구 예시: `이 자산은 현재 기준으로 -2,100원 손실이에요.`
- 보조 문구: `시장 가격은 변동될 수 있어요. 이 화면은 이미 발생한 소비의 기회비용을 보여줍니다.`

## DB 적재, 스케줄링 및 성능

코스콤 CHECK API는 외부 시세 API이므로 매 요청마다 직접 호출하지 않는다. 종목 검색과 기준가 계산은 백엔드 DB를 기준으로 처리한다.

- `investment_asset`: 코스콤 주식/ETF 종목 마스터를 저장한다. 검색 API는 이 테이블에서 종목명/종목코드를 조회한다.
- `investment_price`: 종목별 거래일 종가를 저장한다. `(asset_code, trade_date)`를 복합 PK로 사용한다.
- 화면에는 `investment_price`의 최신 거래일 가격을 `currentPrice`, 선택 월 첫 거래일 가격을 `basePrice`로 표시한다. 별도 테이블 변경 없이 `synced_at`을 현재가 조회/동기화 시각(`quotedAt`)으로 사용한다.
- 기본 가격 동기화 대상: `S&P500 ETF(360750)`, `KOSPI 200 ETF(069500)`, 사용자가 검색 후 선택한 종목
- 매일 스케줄: 백엔드 프로세스가 `KOSCOM_SYNC_TIME` 기준 KST 매일 1회 코스콤 CHECK API를 호출해 종가를 갱신한다. 기본값은 `17:10`이다.
- 배포 직후 초기 적재: 서버 시작 5초 후 `investment_price`가 0건이면 자동으로 코스콤 마스터와 기본 가격을 적재한다. 강제로 매 시작 시 동기화하려면 `KOSCOM_SYNC_ON_START=true`를 사용하고, 수동 실행은 `POST /api/investment/sync`를 사용한다.

관련 환경 변수:

```env
KOSCOM_SYNC_TIME=17:10
KOSCOM_SYNC_ON_START=false
KOSCOM_SYNC_DISABLED=false
KOSCOM_PRICE_SYNC_LIMIT=200
KOSCOM_REQUEST_INTERVAL_MS=1100
KOSCOM_BASE_URL=https://checkapi.koscom.co.kr
KOSCOM_STOCK_MASTER_PATH=/stock/m001/code_info
KOSCOM_ETF_MASTER_PATH=/stock/m001/code_etf_info
KOSCOM_BASIC_QUOTE_PATH=/stock/m001/basic_info
KOSCOM_HISTORY_QUOTE_PATH=/stock/m001/hist_info
```

과거 종가 백필은 코스콤 CHECK API 계약에 과거 일자별 종가 엔드포인트가 제공되는 경우 별도 작업으로 확장한다. 현재 MVP는 “매일 쌓인 실제 종가”를 기준으로 계산하며, 없는 날짜는 임의값으로 보정하지 않는다.

## 완료 기준

다음 조건을 만족하면 투자효과 페이지 요구사항을 충족한 것으로 본다.

- `/investment-effect` 화면이 Figma 와이어프레임의 정보 구조와 문구 방향을 따른다.
- 프론트엔드는 Kopilot 백엔드 API만 호출하고 코스콤 인증값을 직접 다루지 않는다.
- 백엔드는 `CUST_ID`, `AUTH_KEY` 환경 변수를 사용해 코스콤 CHECK API를 호출한다.
- 로컬 `.env`와 배포 환경 변수 설정 방식이 문서화되어 있다.
- 기본 비교군이 S&P500/KOSPI 200 등 지수 ETF와 안정형 비교군 중심으로 구성된다.
- 사용자가 주식이나 ETF를 검색하고 선택한 경우에만 개별 종목 시뮬레이션을 표시한다.
- 주식 종목 마스터, ETF 종목 마스터, 기본 시세 조회 API 사용 목적이 명확하다.
- 소비액, 평가 금액, 예상 손익, 손익률, 기준 시각이 응답과 화면에 표시된다.
- CHECK API 실패, 인증값 누락, 소비액 없음, 손실 결과에 대한 예외 처리가 정의되어 있다.
- 투자 권유가 아닌 참고용 시뮬레이션 고지가 화면에 표시된다.
